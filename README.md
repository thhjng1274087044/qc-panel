# 质检插件服务（_plugin_server）

把质检面板做成飞书多维表格扩展的「运行地址」，本机 Flask 跑服务，内网穿透暴露成 HTTPS，
飞书里点开插件就能用。不需要 opdev 打包、不需要发布到飞书应用市场。

---

## 为什么不需要打包（已从 SDK 源码确认）

`@lark-base-open/js-sdk@1.0.2` 与飞书宿主之间**只有一条通道**：`window.parent.postMessage` 握手协议。

```
页面 → 宿主   {type:"handshake", payload:{proactive:true}}
宿主 → 页面   {type:"handshake", payload:{prefixId}}
页面 → 宿主   {type:"invoke", id, payload:{key:"bitable.WidgetBase_getSelection", params:[...]}}
宿主 → 页面   {type:"callback", id, payload:{res:[...]}}
宿主 → 页面   {type:"event", payload:{eventName, params}}
```

握手类里写死 `allowedHostOrigin = ["*"]`，**不校验来源域名**。所以页面放自己域名、SDK 由自己域名托管，照样通。

两个容易踩的细节：

1. **`res` 必须是数组**。SDK 的 `fe()` 装饰器走批量 `invokeApi`，`runImmediate` 会对返回值
   直接 `.forEach` 分发，回单个对象会报 `forEach is not a function`。
2. **批量项里的真实参数在 `it.p`**，`payload.params` 本身是 `[{c,p,t}]` 数组。

唯一的硬前提：页面必须被 iframe 嵌进飞书（`window.parent !== window`）。
SDK 里 `if (window.parent === window) { this._handshakeStatus = 2; return }`，
否则握手直接判失败，`getSelection()` **不报错、永远挂住**（SDK 自己 70 多秒后才 reject）。

## 启动

```bash
cd E:\质检skill\_plugin_server

# 本机调试（无鉴权，只监听 0.0.0.0 方便局域网看）
python app.py

# 对外提供服务（多线程，带访问口令）
PORT=8776 QC_TOKEN=你的口令 python serve.py
```

Windows 下一键起「服务 + ngrok 隧道」：双击 `run.bat`，窗口里会打印公网地址。**窗口关掉就断。**

隧道已经在跑、只想起服务：双击 **`serve_only.bat`**（只监听 8776，不起隧道，不影响现有公网地址）。
**不要用后台 shell 起**：那种进程挂在终端会话上，会话一结束就被回收（实测活 3~4 分钟后 502）。
要长期常驻就双击 `serve_only.bat` 并把窗口最小化；它有窗口、日志也看得到，比隐藏进程好排错。

**重启前必须确认端口上没有旧进程**。Windows 的 `SO_REUSEADDR` 允许两个进程同时绑 8776，
新进程不报错、`/health` 也照样 200，但请求会**随机落到新老代码上** ——
表现为「改了半天有的请求生效有的没生效」，极难排查（2026-11-09 实测踩到，
旧进程 13:09、新进程 13:43，两个都在监听）。查：

```bash
powershell -c "Get-CimInstance Win32_Process -Filter \"Name='python.exe'\" | ? { \$_.CommandLine -like '*serve.py*' } | Select ProcessId,CreationDate"
```

只留一个，或者先全停再起。

本机地址：

| 用途 | 地址 |
|---|---|
| 入口（按身份出模块卡） | http://127.0.0.1:8776/ |
| 登录（**只给管理员应急**） | http://127.0.0.1:8776/login |
| 假飞书宿主（本地验证面板用） | http://127.0.0.1:8776/host?k=口令 |
| 插件面板（飞书里填这个，**不要带 k**） | http://127.0.0.1:8776/panel |
| 工程量统计 | http://127.0.0.1:8776/qty |
| 账号与授权（仅管理员） | http://127.0.0.1:8776/admin |
| 探针 | http://127.0.0.1:8776/probe?k=口令 |
| 健康检查 | http://127.0.0.1:8776/health |

> 三条通道并存：**飞书身份**（`/api/ident`，日常走这条，零输入）；**主口令**（`QC_TOKEN`，
> `?k=` 或 `X-QC-Token`，管理通道全通）；**口令登录**（`/login`，管理员应急）。
> 面板票据也是 `?k=` 的值（按人签发、带项目号、12 小时过期），让飞书 iframe 在没有 cookie 时也能认出人。

它是**应急入口**：日常让管理员在 `/admin` 把自己的飞书 id 绑上，之后进管理页也不用口令；
确认绑好再把这份文件删掉。

## 内网穿透

飞书插件要求 HTTPS，且宿主要能访问到。四条路实测：

> **放进飞书边栏前先过这一条**：把窗口拉窄到 400px 左右打开候选地址，
> 看到**我们自己的面板**才算过。看到 ngrok 英文拦截页不算失败 —— 点 `Visit Site` 再重载就通了。
> 判定标准是「点了能不能进」，不是「第一次看到的不是我们」。

| 方式 | 结果 |
|---|---|
| **ngrok 免费 + 静态域名** | ⚠️ **能用，但每台设备首次要点一下 `Visit Site`**，且按钮要等约 8 秒才出现。见下方实测 |
| ngrok 付费 | ✅ 干净。付费账号不发拦截页，域名照样固定。改 0 行代码 |
| Cloudflare Tunnel（quick） | ✅ 干净、无拦截页，但域名每次重启都变 |
| localhost.run（SSH） | ⚠️ 能连但限速 6KB/s，SDK 主包下不完 |
| **自有公网服务器 + 域名** | ✅ 最稳。地址固定、无拦截页。见下方「绑自己的域名」 |

### ngrok 免费版在 iframe 里的真实行为（2026-11-10 实测）

**能用，但要过一道门，而且这道门出现得很慢。**

| 时刻 | 看到什么 |
|---|---|
| 打开后 0–8 秒 | **一片空白**（`ERR_NGROK_6024` 的壳已返回，按钮还没渲染） |
| 约 8 秒后 | 出现 ngrok 英文页 + `Visit Site` 按钮 |
| 点 `Visit Site` | 种下 `abuse_interstitial` cookie |
| 重载 / 再打开 | **直接进面板，不再问** |

**踩过一次的坑**：只等 3 秒去查 `button`，结果是空数组，据此判定「新版不渲染按钮、边栏里是死路」——结论是错的。
按钮由 `cdn.ngrok.com/static/compiled/js/allerrors.js` 异步渲染，8 秒才出来。
以后再验这类拦截页，**至少等到 10 秒**，或者直接看截图，别只查 DOM。

拦截按 UA 判定，换 UA 没用：

| 请求 | 结果 |
|---|---|
| 普通 Chrome UA | 拦截页 |
| **飞书 Electron UA**（`Lark/7.20`） | **同样拦截** |
| 不带 UA | 200，正常返回面板 |
| 带 `ngrok-skip-browser-warning: 1` | 200，正常返回面板 |

iframe 加不了请求头，飞书里也去不掉 UA，所以这道门躲不掉，只能点。

**代价**：换电脑、换浏览器、清 cookie 都要再点一次；同一台设备点过就一直好。
域名是静态的，所以重启隧道不会让这道门重新出现。

**没验过的**：飞书 Electron 客户端对 iframe 内第三方 cookie 的持久化策略与 Chrome 未必一致，
`abuse_interstitial` 能不能在飞书里长期存活，需要在真飞书里点一次再重开确认。
真要彻底去掉这道门，用自有服务器那条（`qc.xuyuhang.com` 已解析到 `47.97.125.66`）。

起隧道（**必须加 `--protocol http2`**）：

```bash
cd E:\质检skill\_plugin_server
./cloudflared.exe tunnel --url http://localhost:8776 --no-autoupdate --protocol http2
```

### ngrok（现在的主用方式）

```bash
# 先把代理变量清掉，否则直接报 ERR_NGROK_9009
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy ./ngrok http 8776 --log=stdout
```

三条实测结论，都是踩出来的：

1. **代理变量是隐形地雷。** 本机 `HTTP_PROXY=127.0.0.1:7011`，ngrok 一带上代理就报
   `ERR_NGROK_9009：Running the agent with an http/s proxy is a Pay-as-you-go feature`，
   文案写的是“认证失败”，很像 token 坏了，其实只是代理。`run.bat` 里已先把六个代理变量置空。
2. **免费版在 iframe 里是白屏，不能当插件地址用。** 早期版本警告页能点过去，
   2026-11-10 换上新的错误页后按钮不再渲染（见上节实测表）。免费域名只适合本机浏览器直接调试。
3. **免费域名每次重启都变**。静态域名要付费；免费只能拿随机子域。

两个实测结论：

1. **申请隧道要走代理。** 本机直连 `api.trycloudflare.com` 超时，走 `http_proxy` 才通；
   但边缘节点（`*.trycloudflare.com` 解析到 104.16.x）**直连可达**，所以浏览器侧不需要代理。
   这与 ngrok 正好相反 —— **ngrok 必须无代理，cloudflared 申请时必须带代理**。
2. **申请会失败，要重试。** 实测三次里成功一到两次，失败信息是
   `context deadline exceeded`。`_tunnel_retry.sh` 会自动重试，
   并且只在出现 `Registered tunnel connection` 后才算成功（拿到地址不等于连通）。

```bash
bash _tunnel_retry.sh     # 成功后打印 TUNNEL_OK https://xxx.trycloudflare.com
```

地址**每次重启都会变**。要固定地址：自有服务器直接绑域名；或 Cloudflare Named Tunnel。

### 绑自己的域名（Named Tunnel）

1. 域名 NS 托管到 Cloudflare
2. `cloudflared tunnel login` → `cloudflared tunnel create qc`
3. `cloudflared tunnel route dns qc qc.你的域名.com`
4. `cloudflared tunnel run --url http://localhost:8776 qc`

之后插件地址固定为 `https://qc.你的域名.com/panel`（**不带 `?k=`** —— 带上就是主口令，
人人全通、也认不出人）。

### 部署到自有服务器

把整个目录（含 `img/`、`vendor/`、`data/records.json`）传上去，然后：

```bash
pip install -r requirements.txt
PORT=8080 QC_TOKEN=一串随机字符 python serve.py
```

前置 nginx 反代并配证书即可。`data/qc.db` 是留痕库，首次启动自动建表；
想从零开始就删掉它再启动。

> `IMG_DIR` 默认取项目内 `img/`。旧机器上如果图在别处，用
> `QC_IMG_DIR=/path/to/对比图 python serve.py` 指过去。

## 飞书里怎么配（边栏插件）

我们这个是**边栏插件**（多维表格右侧的插件面板，随选中记录变化），
不是「记录视图插件」，所以**不需要 opdev 打包、不需要 BlockTypeID、不需要上架审核**——
官方文档原话：Vercel / GitHub / localhost / 自己的服务器，只要部署了服务就能跑。

### 添加

1. 打开多维表格 → 顶部/右侧「**插件**」→「**自定义插件**」→「**+ 新增插件**」
2. **运行地址**填 `https://你的域名/panel`
   （**不要带 `?k=`**：带了就是主口令通道，人人全通、也认不出人）
3. 确定。插件列表里出现它，点开即用
4. 点左侧任意记录，右侧应立刻跟着换

前提是那个地址**无拦截页**——先按上面「内网穿透」那节的验证办法过一遍，否则点开是空白。

### 分发给同事

在任意多维表格里打开该插件 → **插件详情** → 「**复制链接**」→ 把链接发群里。
这是官方给的正规分发方式，别人点开就能装。

**一个绕不过的边界**：自定义插件挂在**当前这张 Base** 上，换一张多维表格要再填一次地址。
想「装一次、所有表都能用」只能上架插件市场，而上架要求代码由官方审核、
且文档写死「禁止将多维表格数据向外部发送」——我们把记录和结论落到自己的库，
过不了审，别往那条路投入。

### 边栏宽度

面板常被拖到 320–480px。页面已按此适配：无横向溢出、顶栏不换行、
`≤1180px` 收起详情列、`≤420px` 顶栏收起标题文字（图标照留，状态和两个出口都不砍）。
改顶栏前先在 360px 宽度下看一眼。

打开时如果没选中任何行，面板显示「请在左侧点选一条记录」——不会默认取第一条，避免错位。

### 页面之间怎么走：首页 → 项目 → 返回首页

`/` 是首页，只画**当前这个人有权限的**模块卡片；各项目页右上角都有「返回首页」。

| 页面 | 地址 | 回首页时凭据怎么带 |
|---|---|---|
| 首页 | `/` | 它自己就是首页，不画返回按钮，也不引 `nav.js` |
| 测绘报告审核 | `/panel`（飞书里）/ `/panel?k=` | 带走当前 `k` |
| 工程量统计 | `/qty` / `/qty?k=` | 同上；顶层靠 cookie 时就是干净的 `/` |
| 文件压缩 | `/shrink` / `/shrink?k=` | 同上 |
| 成果水印 | `/watermark?k=` | **不回首页**——它跳到另一台机器上的独立程序（见下） |
| 账号与授权 | `/admin` / `/admin?k=` | 同上 |

#### 成果水印：点进来直接就是原程序（2026-11-10 改）

水印程序跑在内网另一台机器上（`QC_WM_URL`，默认 `http://192.168.0.101:8765`），走 HTTP。

**不能内嵌的硬原因**：混合内容策略。HTTPS 页面里嵌 `http://` 的 iframe，浏览器直接拒绝加载，
控制台一条 `Mixed Content`，页面上是一个白框 —— 和服务通不通无关（服务端探测明明 200）。

**解法不是反代，是顶层跳转**。混合内容只管**子资源**（iframe / script / img / fetch），
**顶层文档导航不受这条约束**：浏览器只会给目标页标一个「不安全」，不会拒绝跳转。所以：

- `/watermark` 先服务端探一次远端（4 秒上限，绕代理直连），**通则直接 302 过去**，不出中转页；
- 不通则停在本服务，把 `err` 和耗时摆出来，给「重试」和「打开原程序」两个按钮；
- 首页那张水印卡带 `target=_blank`，新标签打开原程序，首页留在原地。
- 带 `?stay=1` 才会停在说明页（排障用，也是自测验页面结构时要带的参数）。

**为什么不选同源反代**（把 `/wm/` 转发到内网 8765）：技术上可行（前端是单文件、只有 4 个
`/api/` 绝对路径，改写成 `/wm/api/` 就够），但那样水印文件与成果要经公网隧道中转。
测绘成果外传有合规风险，所以不做 —— 水印流量只走内网。

代价：跳走就离开了本服务，没有「返回首页」；浏览器后退可回。要求**打开页面的浏览器在内网**，
否则跳过去也是打不开。

自测：`_selftest_watermark.py` 36/36（含「权限门 → 302 → 远端停掉时停下来说明」）、
`_wm_click_check.py` 7/7（真浏览器、真 HTTPS 页面点卡片，验证新标签确实落到原程序）。

统一逻辑只有一个文件 `static/nav.js`：页面里写 `<a data-home>返回首页</a>` 就够了，
**模板里不要写死 `href="/"`**。三条硬规则都是踩出来的：

- **回首页的链接必须带票据 `k`。** 飞书 iframe 里第三方 cookie 被拦，`href="/"` 会一路弹回 `/login`。
- **绝对不能用 `target=_top`。** 顶掉顶层窗口后，飞书客户端把这次导航当成外部链接，
  另开一个全屏 webview —— 人就离开飞书界面了（实测踩过一次）。返回首页必须发生在 iframe 内部。
- **能在 iframe 里回得去的前提是「首页也认票据」。** `/?k=<票据>` 让首页带着票据去问 `/api/me`，
  所以 `entry.html` 里 `K` 那段必须留着；票据失效时显示一句说明，不往登录页踢。

配套改动：`_links()` 现在给**每一条**模块链接都签了对应项目的票据（原来只有审核面板带），
否则 iframe 内首页那几张卡点进去还是 302 登录页。票据依然一条只开通一个项目，
拿审核票据手敲 `/qty` 仍然 403。

自测：`_selftest_nav.py` 34/34、`_shot_nav.py` 33/33（均覆盖 `/shrink`；真浏览器里 iframe 内点击后
**顶层 URL 不变**，并在框架内走完「面板 → 首页 → 工程量 → 首页」整条链）。

### 谁能看到：认飞书身份，不看账号口令

2026-11-09 起本服务自带项目级授权：**一个人能看到哪几个模块，由服务端判定**。
原因是实际需求变成了「同一批人里，只有一部分能看工程量统计」，这件事外层程序做不了
（飞书只决定谁能打开这张表）。

不设账号口令：人在飞书里打开面板，宿主把 `bridge.getUserId()`（`ou_…`）给前端，
前端 `POST /api/ident` 换票据，服务端拿这个 id 查 `qc_user.oid` 决定给哪几个模块。零输入。

| 事项 | 由谁负责 | 具体做法 |
|---|---|---|
| 认人 | 飞书（open_id）+ 服务端 | 面板自动取 `getUserId()` → `/api/ident` → 查 `qc_user.oid` |
| 谁能进哪个模块 | 服务端（`qc_user` + `qc_perm`） | 项目级授权：`audit` 审核 / `qty` 工程量。没授权 = 不出这张卡，硬敲地址 403 |
| 新人怎么进来 | 自己打开一次面板 | 没绑过的 id 自动进 `/admin` 的「待开通」，管理员勾模块点开通即可，不用问 id |
| 批量开通 | 管理员点「从人员名单批量建号」 | 读 `data/people.json`（36 人，key 就是 open_id），建成绑好的账号，默认只开审核 |
| 管理员 | 同上 | `role=admin` 默认全通，不看逐条授权（否则改配置会把自己锁外面） |
| 身份怎么带 | 服务端签发 | 顶层浏览器用 `qc_sess` cookie（HMAC，12h）；飞书 iframe 用 `?k=<票据>`（带 uid + 项目号，12h） |
| PC 上做工程量 | 管理员发一条入口链接 | 没有飞书宿主认不出人，给他复制「工程量链接」（30 天票据），点一次换 cookie |
| 离岗 / 换人 | 管理员在 `/admin` 停用 | 停用对已有会话**立即生效**；解绑 id 只是下次进不来 |
| 加权限 / 收权限 | 管理员在 `/admin` 点「编辑」 | 弹窗里勾上即给、去掉即收回，可一次改完角色 + 模块 + 启停；保存后立即生效。操作列只留「编辑 / 启停」，链接、绑定、口令、删除都在弹窗里 |
| 「谁点了通过」的留痕 | `qc_action.actor` | 面板仍从宿主取 `getUserId()`，见下一节 |

**为什么面板要票据、不用 cookie**：飞书桌面端是 Chromium，第三方 iframe 里的 cookie 默认被拦。
票据塞在 `?k=` 里，`panel.html` 原本就会把 `?k=` 原样转发到每个请求，所以前端一行没改。

**票据只开通一个项目**：别人拿到你的审核链接，进不了 `/qty` —— 票据里写了 `p=audit`，
服务端按路径判项目，对不上直接 403（实测见 `_selftest_ident.py`）。

**边界要说准确**：`/api/ident` 收的 open_id 由前端上报，服务端**没有验签**，改请求就能冒名。
这套东西让权限落到人头上、可追溯，**不是不可否认**。要更硬，得拿飞书应用凭证把代码换
`user_access_token` 再反查通讯录；在那之前别把它当身份认证用。票据同理：它是「链接凭据」，
转发给别人别人也能用，所以链接别往群里发，必要时缩短 `perm.TICKET_TTL`。

#### 「我的账号进不去账号与授权」

先分清是哪一种，三种表现对应三个原因：

| 表现 | 原因 | 怎么修 |
|---|---|---|
| 首页根本没有「账号与授权」这张卡，直接敲 `/admin` 是 403 | `qc_user.role` 还是 `user` | 编辑弹窗里虽然有「角色」下拉，但改**自己**会被后端拒绝（自锁防护）。要提权自己只有三条：主口令通道、另一个管理员帮你改、或跑 `perm.set_user(uid, role="admin")` |
| 有卡但点进去报「这个链接只开通了 xx」 | 拿的是别的项目的票据（比如审核链接） | 回首页点卡片，卡片上的链接是当场按当前角色签的 |
| 有卡、点了转圈最后回登录页 | 票据过期（12h）或换了域名 | 重开飞书插件让面板重新 `/api/ident` |
| **页面进去了，内容区写着「未登录或登录已过期」** | **页面内部的接口没带 `?k=`**（见下） | 已在 `static/auth.js` 统一修掉；飞书里需重开一次插件 |

#### 「页面打开了，但里面写未登录或登录已过期」

这句话是 `_auth` 对 `/api/*` 的 401 文案，**不是权限不足，也不是票据坏了**。

根子在「谁来证明我是谁」这件事在两种环境里不一样：

- 顶层浏览器：登录过一次就有 `qc_sess` cookie，页面里的 `fetch('/api/...')` 自动带 cookie，一切正常；
- 飞书 iframe：第三方 cookie 被浏览器拦掉，cookie 这条路根本不存在。页面能打开是因为
  URL 上带了 `?k=`，但**页面里的 fetch 不会自动带 `k`** —— 于是每个接口都是 401，
  管理页把 401 的文案原样印在内容区。

所以「桌面测通了」不代表飞书里能用。修法是 `static/auth.js`：在业务脚本**之前**引，
给页面里所有同源 fetch 自动补 `k`（跨域请求不动），以后新加接口也不会再漏。
不走 fetch 的顶层跳转（如工程量导出 `location.href = '/api/qty/job/<id>/xlsx'`）
包装管不到，必须自己用 `qcWithK()` 包一层。

另外两条兜底：

- **iframe 里裸开**（地址上没有票据）：`Sec-Fetch-Dest: iframe` 时服务端直接 302 `/panel`
  去认人，而不是丢去登录页（飞书里没人有账号口令，去了也是死路）；
- **票据真过期**：`qcExplain401()` 把文案换成「回飞书重新打开面板即可」，而不是一句冷冰冰的
  「未登录或登录已过期」。

自测用 `_selftest_iframe.py`（**19 项**）：把请求里的 Cookie 全部剥掉再打开各页面，
这才是飞书环境的判据。普通浏览器测不出这类问题。

**排查第一句**：`sqlite3 data/qc.db "select name,role,active from qc_user;"`。
管理员判定只看 `role == "admin" and active`，跟 `qc_perm` 里勾了什么都不完全等价 ——
勾满所有模块也不会变成管理员。

**自锁防护**：接口层面挡住了「把自己降级 / 停用自己 / 删自己」，以及「动最后一个管理员」。
这条是踩出来的 —— 2026-11-09 用票据把自己的角色改成 `user`，接口照批，之后 `/admin` 直接 403，
只能去改 SQLite 才救回来。注意 `active` 前端可能传整数 `0` 而不是 `false`，
判断要用 `not bool(v)`，写 `v is False` 会漏（同一个坑连踩两次）。


### 当前登录人：能取到什么、取不到什么

**能取到。** 宿主（飞书客户端）会应答 `bitable.Bridge_getUserId`，SDK 对应的入口是
`bridge.getUserId()`。实测（假宿主 + 真 SDK）确认的请求与返回：

| 方法 | 实际发出的 api key | 返回 |
|---|---|---|
| `bridge.getUserId()` | `bitable.Bridge_getUserId` | 当前登录人的用户 id（`ou_…` 形态） |
| `bridge.getBaseUserId()` | `bitable.Bridge_getBaseUserId` | 在本插件体系内唯一的用户标识 |
| `bridge.getTenantKey()` | `bitable.Bridge_getTenantKey` | 租户标识 |
| `bridge.getInstanceId()` | `bitable.Bridge_getInstanceId` | 本次挂载实例 id |
| `bridge.getEnv()` | `bitable.Bridge_getEnv` | `{ product: 'feishu' \| 'lark' }` |

面板的做法：

- 启动后异步取一次（2.5s 超时），**不阻塞首屏**；取不到就隐藏，不报错、不影响任何操作。
- 优先 `getUserId()`，取空再退回 `getBaseUserId()`（后者只在插件体系内唯一，跨系统对不上人）。
- 拿到 id 后再查一次姓名（`GET /api/people?ids=ou_xxx`），查到就显示「邵宇航」，查不到退回缩写 `ou_…b8d4`，
  鼠标悬停看完整 id。**查不到绝不编造。**
- 提交时 `actor` 存姓名（查不到才存缩写）、`actor_id` 存完整 open_id
  （落 `qc_action.actor_id` 独立列，不只是 payload），签署行与留痕列表都显示本人。

### 姓名从哪儿来：任务表人员字段，不是通讯录

SDK 只给 id，不给姓名。通讯录接口（`contact.user.get`）本应是最直接的路，**但这条走不通**：

```
bot 身份查 21 位同事 → 只有 2 人成功（张阳凡、邵宇航，都在办公室）
其余 19 人一律 41050 no user authority error
   房产测绘部：陈挺、瞿璐伊、黄玲玲、余菲菲
   工程测绘部：周琴晓、柯洪啸、鲍霞、林忆婷、林露嘉、杨海营
   总工办：向国平
```

原因是应用的**通讯录数据权限范围**默认只覆盖创建者所在部门，不是接口坏了。
即使拿到应用密钥直接调 API，结果一样——这是权限范围，不是调用方式问题。

> **「权限开了」为什么还是 41050** —— 飞书这里是两层，常被混为一谈：
> ① **API 权限（scope）**：`contact:contact.base:readonly`，决定「能不能调这个接口」；
> ② **数据权限范围**：决定「这次调用能看见哪些人」，默认「仅创建者相关部门」。
> scope 未开时报的是 `99991672 Access denied ... scopes is required`；现在报 `41050 no user authority error`
> = scope 已通过、**卡在范围**。改的位置也不同：scope 在「权限管理 → API 权限」，
> 范围在「权限管理 → **数据权限** → 通讯录权限范围」，要选「全员」或加指定部门。
>
> 2026-11-09 09:49 在 scope 已开的状态下复测（35 人）：**bot 只查到 1 人（张阳凡，办公室）**，
> 其余 34 人仍 41050；同一个人换 `--as user`（邵宇航个人授权）立刻返回姓名 → 证实接口与参数都正常，
> 差异只在数据范围。这一步在开放平台网页上，代码侧绕不过去。
>
> **当前取舍**：36 人本地映射已够用（覆盖全部在任务表里出现过的人 + 审核人本人），
> 所以不接实时通讯录兜底。日后开放数据范围，只需在 `app.py` 的 `/api/people` 里加一路：
> 本地 miss → 调 `contact.user.get` → 两边都不中才退回缩写。

**真正可用的路：任务表的人员字段。** 飞书返回的单元格值本身就是 `{id, name}` 成对：

```json
"项目经理": [{ "id": "ou_94f5329a81c990f4ea977f9dc2202e7f", "name": "王奔阳" }]
```

读记录就有姓名，**完全不需要通讯录权限**。`build_people.py` 把任务表里五个人员字段
（项目经理 / 任务参与人员 / 质检上传人员 / 本部员工业务辅助判断 / 创建人）扫一遍，
生成 `data/people.json`：

```bash
python build_people.py      # 扫 5000 条记录 → 35 人，再并入手工补录 → 36 人
```

扫描结果：4600 条记录里出现过 **35 个不同的人**，覆盖工程测绘部、房产测绘部、总工办，
包含通讯录查不到的林露嘉、陈挺、向国平等人。

**两个已知缺口**（都写在这里，不假装没有）：

1. **不参与具体任务的人查不到。** 典型就是审核人自己——办公室的人不出现在任务的人员字段里，
   所以 `data/people.local.json` 里手工补了 2 条。这份文件是手工维护的，不会被 `build_people.py` 覆盖。
2. **映射是快照。** 新人入职、换部门要重跑 `build_people.py`。查不到就显示缩写，功能不受影响。

**根治办法**：把应用的通讯录权限范围改成「全员」或至少包含工程测绘部 + 房产测绘部 + 总工办
（开放平台 → 应用 → 权限管理 → 数据权限 → 通讯录）。改完通讯录接口就能兜住所有人，
`people.json` 退化成缓存。这一步要在管理后台操作，代码里做不到。

**必须说清的边界：服务端不验签。** `actor_id` 是前端从宿主拿到再 POST 上来的，服务端只当字符串存。
理论上有人改请求就能冒名。要防抵赖，得让服务端自己用 `user_access_token` 调通讯录接口反查这个人是谁，
拿到的是「飞书认证过的身份」再落库——这一步没做。所以现在的留痕是**可追溯**，不是**不可否认**。

## 三道闸：凭什么说「右边就是左边选的那条」

1. **唯一键**。全程只认 `recordId`，由 `bitable.base.getSelection()` 直接给出。
   不用任务编号——本表存在同任务号 2 条记录（`GC2508003`、`GC2506021`），按任务号取会串行。
2. **变化即清**。换记录先清空 `S.rec`、盖骨架屏、禁用全部按钮，再取数、再渲染；
   自增 `seq` 作废旧请求，晚到的结果直接丢。切换期间点不了按钮，杜绝「看 A 判 B」。
3. **提交复核**。点按钮那一刻重新取一次 `getSelection()`，对不上就弹拦截窗：
   不写飞书、不留痕，并把「本次判定绑定」和「左表当前选中」并排列出来。

跟随用 `getSelection()` 轮询（1200ms）为主，`onSelectionChange` 事件为辅。
飞书 iframe 失焦期间事件会丢，轮询是必需的兜底。

## 人工怎么点：三个出口

AI 只做预审，最终结论由人下。面板底部三个动作，覆盖全部情况：

| 你要做的 | 点哪个 | 后端 action | 落库 conclusion | 必填 |
|---|---|---|---|---|
| 同意 / 放行 | **通过** | `确认` | `通过` | —（可带附言） |
| 退回整改 | **不合格 · 退回** | `打回` | `不合格` | 问题说明；问题类型可选 |
| 只提意见、结论不变 | **附言** | `附言` | 不动 | 意见内容 |
| 推翻自己上一次判定 | **撤销** | `撤销` | 回到 AI 原判 | — |

三条硬规则：

1. **AI 判不合格、人要放行 = 改判，必须写理由。** 点「通过」先弹改判窗，理由为空点不动。
   理由写进意见说明，前缀是「通过（人工改判，AI 原判 不合格）：」。
2. **判不合格不写说明，提交不了。** 只说「不合格」没人知道要改什么。弹窗里的问题类型
   是多选 chips（面积对账 / 点位对账 / 高程点 / 清单缺项 / 意见栏空 / 空白模板 /
   材料不齐 / 超期 / 其他），选中就拼成 `[P-013,E15]` 前缀存进备注。
3. **附言不动结论，也不打断已决策状态。** 已通过/已退回的记录都能补一句；
   补完 `state` 仍是原来的决策 —— `latest_action()` 会跳过附言，否则记录会莫名退回「待确认」。

弹窗打开期间 `S.modal=true` 暂停跟随左表（否则背景行被切走，人在弹窗里写的内容会写到
另一条记录上）；关闭恢复跟随，真正提交时还有第三道闸再核一次。

### 写飞书字段的成品句

后端返回 `fb_text`，前端在弹窗里实时预览，可直接用：

| 场景 | `fldtwiy2VU 审核意见说明` |
|---|---|
| 通过（与 AI 一致） | `通过：经人工复核，与 AI 预审一致` |
| 通过（改判） | `通过（人工改判，AI 原判 不合格）：<理由>` |
| 退回 | `不合格（P-013,E15）：<说明>` |
| 附言 | `<意见>`，追加写入，不改原句 |

`flduuylUz8 ai审核意见` 永远只写 AI 原判、不被覆盖 —— 这样才分得清「AI 判错了」
和「人同意 AI」。

### 写回飞书：由点按钮的那个人写，不是应用

**身份问题先说清。** 服务端如果用应用密钥（bot）写，飞书那边「修改人」会记成应用，
查不出是谁判的。这里换了一条路：**请求由浏览器发出**，宿主用当前登录人的身份调
`table.setCellValue`，修改人就是他本人。服务端全程不持 token、不调飞书。

```
点「通过」 → POST /api/decide（服务端只写本地 qc.db，拿回 action_id）
          → SDK table.setCellValue(字段, 记录, 值)   ← 这条用登录人身份
          → POST /api/decide/receipt（把成没成回报给服务端）
```

**这一步顺带解决了「坏字段」。** `审核意见 fldMTrdVhY` 的选项源表服务端读不到
（返回 `800030104`），但客户端以登录人身份 `getFieldMetaList()` 能读到全部选项。
所以结论能写进这个本该最合适的字段，不用去借 `flduuylUz8`。

**默认关闭。** `QC_WB_ENABLED=0` 是默认值：只写本地，不碰飞书。要开就把 `run.bat`
里那行改成 `1`，或直接设环境变量。

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `QC_WB_ENABLED` | `0` | 总开关 |
| `QC_WB_CONC_FIELD` | `fldMTrdVhY` | 结论写哪个字段（单选，按选项文本匹配） |
| `QC_WB_NOTE_FIELD` | `fld01QMpX1` | 说明写哪个字段（文本），留空则不写 |
| `QC_WB_ACTOR_FIELD` | 空 | 人员字段 id，填了就以登录人 open_id 写入 |

**写不进去会说清原因，不会假装成功**：

| 情况 | 表现 |
|---|---|
| 当前人在此表只读 | 直接返回「宿主拒绝写入」，不去试错 |
| 字段没有对应选项 | 报「字段无「通过」选项（现有：通过/不合格）」，不瞎写 |
| 宿主返回 false / 抛异常 | 原文记进 `qc_writeback.error`，界面提示「飞书写入失败：…」 |
| 本地已落库、飞书没写成 | 决策保留，回执单独记一条 `ok=0`——两者分开才查得清 |

**回执表 `qc_writeback`**：`record_id / action_id / field_id / value / ok / error /
by_id / by_name / written_at`。`by_id` 是宿主判定的登录人 open_id，不是前端自报。

**注意两点：**

1. **撤销不往回清字段**。点撤销只把本地结论退回 AI 原判，飞书上已经写进去的字还在。
   要清得手工改，或者后面补一条「撤销即写空」。
2. **仍然不是不可否认**。身份是宿主给的，比自报强得多；但如果有人绕过面板直接调接口，
   服务端仍不验签。要彻底做到，只能服务端拿 `user_access_token` 反查，那就要把 token
   交给服务端——权衡后没做。

## 第二个模块：工程量统计（`/qty`）

给内业算工程量用：传 dwg/dxf（可多份）+ 工程量清单（xls/xlsx，可选），出「图面实测 + 清单对撞」。

### 三条口径（和审核模块一致，别在这里另立一套）

1. **两种图面值分开列，不合并**：`图层合计`（按图层把线长、闭合面积、点位个数加起来）与
   `图面注记`（图上写出来的 `26673.0平方米` 这类文字）。两者不一致时只写说明 —— 图框会吞注记、标注会重复计，属常见现象。
2. **单位不一致就不比**：清单写「工日」、图面只有面积，直接 `无法对位`，不硬凑数字。
3. **差异只说明**：本模块**不判合格/不合格**，只出「对得上 / 对不上 / 对不上多少」。判定归审核模块和人。

### 图层命名约定（决定统计准不准）

本部门图层的命名习惯就是「口径-名称」，直接拿来当统计口径，比按实体类型猜可靠：

```
长度-雨水直埋φ200A型缠绕管   → 按线长合计，单位米
个数-雨水500×500砖砌井      → 按实体个数，单位个
面积-实测范围               → 按闭合多段线面积，单位平方米
```

没有这三种前缀的图层**不硬凑**：按主要实体类型推一个口径（线→米、块/点→个、闭合多段线→平方米），
在界面上标「推断」；图框、`0` 层、`Defpoints` 这类整图通用层直接跳过，推出来只会是噪音。

### dwg 怎么读

ezdxf 读不了 dwg，走 **ODA File Converter**（本机已装 27.1.0 → `C:\Program Files\ODA\ODAFileConverter 27.1.0`）。
没装时接口直接报错并给出替代方案（在 CAD 里另存 dxf），**不返回空表** —— 空表比报错危险，看的人会以为「图上真没有」。

### 清单解析的实际坑

- 表头是两级的：`工程量` 下面再分 `数量` / `单位`；同一行右边还有 `收费单价` 的 `单位`。
  **取「数量列右边第一个『单位』」**，取最后一个会拿到单价单位 —— 实测样本 `XDL26109948` 一开始就是这么错位的。
- 遇到 `合计` 行停止；序号列只认纯数字，否则自增。
- 任务号（`XDL…` / `GC…` / `WLJC…`）从任意单元格里正则捞，常写在右上角。

### 输出

界面四个页签：工程量汇总 / 清单对照 / 图层小计 / 文字注记。
导出 xlsx 同名四张表，可直接贴进结算清单底稿。

## 第三个模块：文件压缩（`/shrink`）

一句话：把 **pdf / jpg / png 压到指定体积以下（默认 4 MB）**，输出还是原来的格式，文件名加 `_压缩`。

**为什么全在浏览器里做**：这条服务的出口是公网隧道，带宽只有几十 KB/s，
一份 20 MB 的 PDF 传上来要十几分钟；而且测绘资料不该在服务器上留副本。
所以压缩用的是 pdf.js + pdf-lib，文件从本地磁盘直接进浏览器内存，**不上传、不落盘**，
关掉页面就没了（界面里有这句提示）。服务端只发页面和四个 JS 库（`static/shrink/`，约 2 MB）。

| 类型 | 怎么压 | 输出 |
|---|---|---|
| 扫描件 PDF | 每页按目标宽度重渲染成 JPEG，再用 pdf-lib 拼回 PDF。八档阶梯（1653px@0.62 → 800px@0.30），先抽样 3 页估算，不够再降 | `.pdf` |
| 文字型 PDF | 同上 —— **这一点必须知道** | `.pdf` |
| jpg / jpeg | canvas 重编码，先降质量再降尺寸 | `.jpg` |
| png | canvas 重编码（PNG 的质量参数无效，只能降尺寸） | `.png` |

**代价说清楚**：PDF 一律走「每页转图片再拼」，所以**文字层、书签、表单、链接都会丢**，
压完的 PDF 是纯图片，搜不到字也复制不了。界面上对含文字层的文件会标黄「含文字层，压完会变成图片」——
不是猜的，是读第一页 `getTextContent()` 数出来的。图纸、扫描件、盖章件无所谓；要保留文字层就得走服务端
（PyMuPDF 只重压图片 XObject、保留内容流），那是另一套实现，目前没做。

压不到目标不会报错，但会标黄「已压到最小档，仍超目标」并给出实际体积 —— 不假装成功。

权限：项目号 `shrink`，和其它模块一样在 `/admin` 勾。没勾的人硬敲 `/shrink` 是 403。
`/static/shrink/*` 免鉴权（纯前端库、不含任何数据），页面本身要凭据。

```bash
python _selftest_shrink.py  # 31 项：门、权限、页面内容、四个库、首页卡片指对 /shrink、管理页勾选项对齐
python _shot_shrink.py      # 16 项：真浏览器压一份 4.2MB 的 PDF，断言 <4MB、blob 下载、落盘体积一致
```

实测：4.24 MB（14 页 A4、含文字层）→ **1.87 MB**，减少 56%，输出仍是 14 页 PDF。

## 留痕四表

```sql
qc_run(id, record_id, material_hash, rule_ver, worker_ver, started_at, finished_at, status)
qc_result(id, run_id, record_id, ai_conclusion, conclusion, reason, evidence_img, mode, version, created_at)
qc_action(id, record_id, run_id, action, actor, actor_id, note, payload, created_at)
qc_writeback(id, record_id, action_id, field_id, value, ok, error, by_id, by_name, written_at)
qc_diag(id, source, payload, ip, ua, created_at)
```

- **幂等**：`qc_run.id = "{record_id}@{material_hash}"`，同一份材料重复访问只建一条 run。
- **AI 原判不被覆盖**：`ai_conclusion` 永远保留 AI 的判定，人工结论写 `conclusion`。
  撤销时 `conclusion` 回退到 `ai_conclusion`，历史动作留在 `qc_action` 里只追加。
- `material_hash` = 附件名 + 结论文字 + 模板的 sha1 前 16 位。材料一变指纹就变，旧判定自动失效。
- **`actor_id` 是独立列，不是埋在 payload 里**。写飞书人员字段要的是 open_id，取这个：
  `[{"id": actor_id}]` —— 只认 id，`actor`（姓名）写进去无效。
  老库由 `_migrate_actor_id()` 自动补列并从 `payload.actor_id` 回填一次，不用手工迁移。
  `/api/state/<rid>` 与 `/api/record/<rid>` 都会返回它（`actor_id` / `decided_by_id`）。
- **`qc_action` 与 `qc_writeback` 是两件事**：前者是「人做了什么决定」，后者是「飞书那边
  到底变没变」。分开存才查得清「库里判了但表里没写」这种半成功状态。
